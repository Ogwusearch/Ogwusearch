# BACKLOG RULES

## Rule 1

A backlog item is **not** an active task.

## Rule 2

New ideas go here before they interrupt the current focus.

## Rule 3

Ideas must eventually be reviewed.

## Rule 4

Duplicate ideas should be merged.

## Rule 5

Projects that no longer have a clear purpose should be archived.

## Rule 6

A backlog item becomes active only when it is deliberately selected.

---

# PRIORITY LEVELS

### P0 — Critical

Blocking an active system or requiring immediate attention.

### P1 — Current

Directly supports the current milestone.

### P2 — Planned

Important future work.

### P3 — Exploration

Worth investigating.

### P4 — Idea

Interesting but not currently scheduled.

---

# REVIEW PROCESS

During backlog review:

```text
BACKLOG
   ↓
REMOVE DUPLICATES
   ↓
REMOVE IRRELEVANT ITEMS
   ↓
GROUP RELATED ITEMS
   ↓
PRIORITIZE
   ↓
SELECT NEXT WORK
   ↓
CURRENT FOCUS
```

Only selected work moves into `CURRENT_FOCUS.md`.

---

# CURRENT BACKLOG RULE

The backlog may grow.

**The active focus must not.**

At any given time, there should be one primary objective.
